Goal

Take drafted posts (status = Drafted), apply LinkedIn-specific formatting rules (staircase layout, 3-line blocks, UPPERCASE headers, emoji placement, Hindi sentences, character count, readability), generate a code-block preview, and get user approval to advance the post to Previewed status.

System: This is a BMAD workflow — interactive, human-in-the-loop. The agent applies formatting rules, the user previews and approves (or requests changes). ALL data reads and writes go through n8n webhooks. The agent has ZERO direct DB/API access.

Scope: LinkedIn only (v1). Formatting rules are platform-specific — this workflow implements the LinkedIn v1 ruleset.

Agent Instructions

Overview

This workflow transforms raw drafted posts into LinkedIn-ready formatted content. The agent takes a post that has passed through B-Drafting (status = Drafted), applies the full LinkedIn v1 formatting ruleset, generates a code-block preview, and gets user approval to advance the post to Previewed status. ALL data reads and writes go through n8n webhooks — the agent has ZERO direct DB/API access.

Agents Involved

Pixel (flex-crafter): Drives the entire formatting flow — fetches drafted posts, applies formatting rules, generates previews, and manages the approval cycle.

Pre-requisites

  • The post MUST be in Drafted status (came through the B-Drafting workflow)
  • The post must have raw content (body text) available in the post record
  • The formatting-rules.csv reference file should be loaded for rule verification

Execution Flow

Phase 1: Post Selection (Step F.1)

  1. Fetch Drafted Posts: POST to sma-fetch-post with { "status": "Drafted" }. Retrieve all posts waiting for formatting.
  2. Present Options: Show the user a numbered list with each post's title, brief topic summary, and scheduled date.
  3. User Picks: User selects one post to format.
  4. Update Status: POST to sma-update-post to set the selected post's status to Formatting. This prevents another session from picking the same post.
  5. If no drafted posts exist: Inform the user and exit. Do NOT proceed with an empty selection.

Phase 2: Apply Formatting Rules (Step F.2)

This is the core of the workflow. Apply ALL of the following rules to the raw draft content:

Rule 1: Staircase Formatting

Structure the post using a "staircase" layout. Each visual section should have progressive indentation or line breaks that create a descending visual flow. Start with a punchy hook line (standalone), follow with short blocks separated by blank lines. Each block is a distinct thought. Never dump a wall of text.

Rule 2: Maximum 3-Line Blocks

Never write more than 3 consecutive lines of text without a blank line separator. This is a HARD rule. If a paragraph has 4+ lines, split it. Aim for 1-3 lines per block. Ensures readability on mobile devices.

Rule 3: UPPERCASE Headers

Use UPPERCASE only for section headers, and use them sparingly (2-3 per post maximum). Do NOT use UPPERCASE for emphasis within body text.

Rule 4: Emoji Placement

Maximum 3 emojis per post. Place them ONLY at tension or transition points. Never use emojis as decoration, bullet markers, or line starters.

Rule 5: Dash Replacement

Replace ALL dashes with proper punctuation (period, comma, colon, parentheses). Exception: - for bullets and —> for flow arrows are allowed.

Rule 6: Bullet Formatting

All bullets must use the format - (space, hyphen, space). Not •, not *, not –.

Rule 7: Flow Arrow Formatting

When showing a process or progression, use the format: A —> B —> C (em-dash + greater-than sign).

Rule 8: Hindi Sentences

Maximum 3 Romanised Hindi sentences per post. Use them ONLY at emotional peaks. Hindi sentences must NOT contain content that needs to be vector-searchable (causes 15-25% lower accuracy in semantic search).

Rule 9: Character Count

The formatted post must be between 800 and 1600 ASCII characters (inclusive). This is a STRICT range. Count characters AFTER all formatting is applied.

Rule 10: Readability — FK Grade 7

Target Flesch-Kincaid Grade Level 7 or below. Short sentences (15 words average), simple words (2 syllables average), active voice, no jargon without explanation.

Rule 11: CTA with Positioning + Follow

Every post must end with a CTA that includes: (1) a positioning statement (who you are / what you do) and (2) a follow prompt (telling the reader to follow for more).

Rule 12: Hashtags

Add 3-6 hashtags at the very end of the post (after the CTA, separated by a blank line). No more than 6, no fewer than 3.

Phase 3: Preview Generation (Step F.3)

  1. Code Block Preview: Render the fully formatted post inside a markdown code block.
  2. Stats Summary: Show character count (800-1600), emoji count (0-3), Hindi sentence count (0-3), hashtag count (3-6), approximate FK Grade Level.
  3. Ask User: "Preview theek hai? Koi changes chahiye?"

Phase 4: User Approval (Step F.4)

  1. Approve: POST to sma-update-post with status = Previewed and the formatted content. Suggest C-Review workflow.
  2. Request Changes: Loop back to F.2 (apply specific changes) then F.3 (regenerate preview). Do NOT re-apply all rules from scratch.
  3. Reject: Revert status to Drafted. Exit workflow.

Key Constraints

  • LinkedIn only (v1), one post formatted at a time
  • Agent has ZERO direct DB/API access — everything through n8n webhooks
  • ALL 16 formatting rules (FR01-FR16) must be applied — none are optional
  • Character count (800-1600) is a HARD limit, not a suggestion
  • Code-block preview is MANDATORY before approval
  • Never invent post content — only format what exists in the draft
  • All user communication in Hinglish (Hindi-English mix)
  • If webhook fails, retry once, then report to user with n8n workflow name

What NOT to Do

  • Do NOT rewrite the post content — only FORMAT it
  • Do NOT add new ideas, examples, or stories not in the original draft
  • Do NOT use bold, italic, or underline formatting (LinkedIn plain text only)
  • Do NOT exceed 3 emojis, 3 Hindi sentences, or 6 hashtags
  • Do NOT skip the staircase layout
  • Do NOT approve a post that violates any formatting rule
  • Do NOT proceed without user confirmation at F.4
  • Do NOT show raw JSON to the user

Error Handling

  • Webhook failure (fetch): Retry once after 5 seconds. If it fails again, report n8n workflow name and halt.
  • Webhook failure (update): Retry once. If it fails again, warn user but provide formatted content locally.
  • Character count out of range: Automatically adjust (trim or expand) and show the user what changed.
  • Post has no raw content: Do not attempt to format. Suggest B-Drafting.

Success Criteria

  • Post formatted with ALL 16 LinkedIn v1 rules (FR01-FR16) applied
  • Character count within 800-1600 range
  • Code-block preview shown to user
  • User explicitly approved the formatted version
  • Status updated to Previewed in MongoDB
  • Formatted content saved to post record
  • No formatting rules violated in final output

What You Do

A previous formatting session was interrupted. The agent must recover gracefully and let the user decide how to proceed.

Actions

1. Present the Interrupted Post

Show the user the post found with Formatting status: title, topic/brief summary, date it was scheduled for, whether any formatted content was partially saved.

"Ek post mila jo pehle se formatting mein tha — lagta hai last session beech mein ruk gaya tha."

2. Ask User How to Proceed

  1. Resume formatting this post — Continue from where it was left off.
  2. Abandon and pick a different post — Revert status to Drafted, proceed to F.1.
  3. Abandon and exit — Revert status to Drafted, exit workflow.

Option 3 — Abandon + Exit: Revert, then exit.

Error Handling

If the revert webhook fails: Still proceed with the user's choice. The post may need manual status correction later.

What NOT to Do

  • Do NOT auto-resume without asking the user
  • Do NOT leave the post stuck in Formatting status if user wants to abandon
  • Do NOT discard any partially formatted content without user consent

Step F.2 — Apply Formatting Rules

Agent: Pixel (flex-crafter)  |  Trigger: User selected a post in F.1 (or resumed from 01b with raw draft in memory).

What You Do

This is the CORE step. Take the raw drafted content from B-Drafting and apply ALL 16 LinkedIn v1 formatting rules. You are FORMATTING, not rewriting. The substance, arguments, voice, and core message MUST be preserved.

Input

  • selected_post.raw_content — the raw draft text
  • selected_post.title, topic, content_format, hook_framework, cta_framework, tone

Formatting Rules — All 16 in Order

PHASE 1: STRUCTURE (FR01, FR02, FR11, FR15, FR16)

Rule 1 — Staircase Formatting (FR01, P2)

Restructure the post into a "staircase" visual flow. Start with a punchy hook line (standalone, 1 line max). Follow with short blocks separated by blank lines. Each block is a distinct thought. Lines within a block can vary in length.

CORRECT:
I shipped 3 features last year.
All three flopped.

Not a single user asked for them.
Not one.

WRONG:
I shipped 3 features last year. All three flopped. Not a single user asked for them...
Rule 2 — Maximum 3-Line Blocks (FR02, P1)

HARD rule, non-negotiable. Scan every paragraph. If any has 4+ consecutive lines, split it. Aim for 1-2 line blocks as default, 3-line for emphasis.

Rule 3 — One Idea Per Post (FR15, P2)

Verify the draft focuses on ONE core idea. If the draft covers multiple topics, identify the strongest one and trim the rest. Do NOT rewrite to merge ideas.

Rule 4 — Whitespace Breathing Room (FR16, P2)

Generous whitespace between blocks. Every block separated by at least one blank line. The post should feel "airy", not dense.

Rule 5 — Character Limit: 800-1600 (FR11, P1)

Enforced last. Target: 800-1600 ASCII characters inclusive.

PHASE 2: TYPOGRAPHY (FR03, FR04, FR05, FR06, FR07)

Rule 6 — No Bold/Italic/Underline (FR03, P1)

Remove ALL **bold**, *italic*, __underline__ markers. Convert important headers to UPPERCASE (max 2-3 per post). UPPERCASE is for section headers ONLY.

Rule 7 — Replace Dashes with Punctuation (FR04, P1)

Replace ALL dashes used as em-dashes/en-dashes with proper punctuation. Exceptions: - for bullets and —> for flow arrows.

Rule 8 — Bullet Format: - (FR05, P1)

ALL bullets must use - (space, hyphen, space). Replace •, *, –, →, > etc.

Rule 9 — Numbered Lists: 1. (FR06, P2)

Numbered lists use digit.space format. Not 1) or (1).

Rule 10 — Flow Arrows: A —> B —> C (FR07, P2)

Replace ->, →, -->, => with —> (space, em-dash, greater-than, space).

PHASE 3: LANGUAGE & READABILITY (FR08, FR09, FR10)

Rule 11 — Maximum 3 Emojis (FR08, P1)

Maximum 3 emojis. Place ONLY at points of maximum emotional tension, transition, or buildup. Strategic placement: hook line, tension/pivot point, CTA. Never as bullet markers or decoration.

Rule 12 — Maximum 3 Hindi Sentences (FR09, P1)

Maximum 3 Romanised Hindi sentences at emotional peaks only. Hindi must NOT contain vector-searchable content. Each Hindi sentence under 15 words.

Rule 13 — FK Grade 7 Readability (FR10, P1)

Average 15 words per sentence. Average 2 syllables per word. Active voice. No jargon without explanation. FK Grade ≈ 0.39 × (words/sentences) + 11.8 × (syllables/words) − 15.59

PHASE 4: FOOTER (FR12, FR13, FR14)

Rule 14 — CTA Line 1: Positioning Statement (FR12, P1)

1-sentence positioning statement answering: "Who is this person and why should I follow them?"

Rule 15 — CTA Line 2: Follow Invitation (FR13, P2)

1-sentence follow prompt specific about what the reader gets by following.

Rule 16 — Hashtags at End Only (FR14, P1)

3-6 generic hashtags at the very end. #CamelCase format. Mix broad + niche. Never in body text.

Final Check: Character Count Enforcement (FR11)

After ALL 16 rules applied, count total ASCII characters. Target: 800-1600.

  • Under 800: Expand key points with concrete examples. Do NOT pad with filler.
  • Over 1600: Tighten sentences, cut redundant words, remove weakest body block. Do NOT cut hook/CTA/footer.
  • Still out of range after 2 attempts: Flag to user with current count.

Max 3 consecutive lines per block. Each block one distinct thought. Blank line between every block. UPPERCASE headers for section transitions (max 2-3). Bullets: - , flow arrows: A —> B —> C. No bold/italic/underline. All dashes replaced with punctuation.

1-2 lines. Clear, memorable phrasing. Works as standalone insight. Often preceded by UPPERCASE header.

1-2 lines. Genuine question or prompt. Relates to post topic.

1 sentence. Who you are + value. Consistent across posts. Confident, not salesy.

6. Follow Line

1 sentence. Specific about value. Action-oriented.

7. Hashtags

3-6, #CamelCase, after follow line, separated by blank line. Mix broad + niche. Never in body.
